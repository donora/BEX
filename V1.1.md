# BEX v1.1 — from detections to a species list

v1.0 answers *how good is each model, window by window?* v1.1 adds the question
a survey actually asks: **which species were here?** It does that by comparing
the rules that turn a model's detections into a species list, including a
middle tier of "probably here, an expert should check".

Compare's species lists (V1 C2) already do the simplest form: a species is
listed for a recording after *k* detections above its θ. v1.1 makes the rule
itself the thing under study.

Status key: **built** · **agreed** · **proposed** (not yet discussed) · **open** (needs a decision)

## The page

### P1. A new page — built, named *Survey protocol*

**3 · Survey protocol**, step 3 in the navigation bar (named 2026-10-05; it was
*Survey rules* while being built). Alternatives considered: *Species lists*,
*Presence*, *Detection rules*, *Biodiversity readout*. The page needs labelled
data for everything except the lists themselves (P7).

It reads the sidebar as every page does (models, judge, threshold rule,
threshold set). On top of that it adds **one** new setting, the survey rule
(P3), which lives on the page and is not added to the sidebar. That could
change if other pages start to use it (open).

## The model of the problem

### P2. The survey unit — agreed

The thing a list is made for. **v1.1 uses the recording** (SNE's are about an
hour each). The engine takes the unit as a parameter so
that **fixed blocks** (every 10 / 20 / 60 min of a recording) can follow without
a rewrite. Truth for a unit is the species annotated anywhere in it.

Rolling windows (any 60 min) are left out. They make overlapping units that
are not independent, which complicates every count on the page.

### P3. The survey rule: three tiers — built (bouts not yet)

For each (unit, species, model) the rule gives one of:

- **firm**: report it without review;
- **check**: possibly present, so an expert listens before it is reported;
- **not found**.

A rule is two conditions, **firm** and **check**, where firm is stricter
than check. Each condition is built from the same parts:

| part | meaning | example |
|---|---|---|
| score bar | which θ a window must clear | the sidebar's θ, or the θ at a stricter / looser precision floor |
| count *k* | how many windows must clear it | ≥ 3 |
| within *W* | …inside any span of this length (blank = anywhere in the unit) | within 20 s |

Examples it can express:

- *firm* = ≥ 5 windows anywhere in the recording; *check* = ≥ 1 window.
- *firm* = ≥ 3 windows within 20 s; *check* = ≥ 1 window.
- *firm* = 1 window at precision ≥ 0.99; *check* = 1 window at precision ≥ 0.8
  (two score bars, i.e. hysteresis).

Open: whether to add **bouts** (separate song events, with windows merged
across gaps shorter than *g*) as a count option. "Sang in 3 separate bouts" is
stronger evidence than "3 windows in a row", because one noise source (a
stream, a fan, a persistent impostor) tends to produce a single long run.
Proposed for v1.1 if it is cheap, otherwise later.

C2's one-tier rule is the special case *firm = check*, so C2 can be rebuilt on
the same engine (P9).

### P4. Scoring a rule — built

Each tier is checked against the annotations, giving a three-tier version of
C2's outcomes:

| | annotated in the unit | not annotated |
|---|---|---|
| **firm** | firm, right | firm, **wrong** (an error that ships unchecked) |
| **check** | check, real | check, not there (wasted expert time) |
| **not found** | **missed** | — |

The headline statistics, per model:

- **Firm precision**: the share of firm calls that are real. This is the number
  that has to be high, because nobody checks them.
- **Recall after review**: (firm right + check real) / annotated. It assumes
  the expert's check is perfect (said on the page).
- **Review load**: check items per recording, and per hour of audio. Later
  this could be expert minutes, at a configurable time per check.
- **Firm recall**: what you get with no expert at all.
- **Missed**, by species, which are the birds no rule rescues.

The geofilter judge is handled as in C2: a species shown only without the
filter has its own outcome, and is not silently counted as found.

### P5. The sweep, and what "optimal" means — built

The trade-off described in the request: **loosen the score bar to catch more
birds, then raise the count *k* to keep firm calls trustworthy.** The sweep is
over:

- the precision floor that sets θ (e.g. 0.5 → 0.99), applied per species as the
  sidebar rule does;
- firm *k* (1 → 20), and optionally *W*;
- check *k* (usually 1).

There is no single optimum, so the page asks for **constraints** and
finds the best rule that meets them:

> Firm precision ≥ **95 %**, at most **N** checks per recording → the rule with
> the highest recall after review.

Views:

1. **Heatmap per model**: precision floor × firm *k*. The colour is recall
   after review, the cells that break the constraints are hatched out, and the
   best cell is marked. This shows the "lower the floor, raise *k*" ridge
   directly.
2. **Trade-off curve**: review load (x) against recall after review (y), one
   point per rule, with the Pareto front drawn per model. Clicking a point
   loads that rule into P3.
3. A readout of the chosen rule in words ("firm after 4 detections at
   precision ≥ 0.7; anything less is checked"), and how it compares with the
   current sidebar rule at *k* = 1.

**Speed.** The sweep needs to be cheap. For each detection, work out once the
loosest precision floor at which it would still clear its species' θ (θ is
monotone in the floor). After that, every floor in the sweep is a filter on
detections plus a group-by count, with no re-resolving of thresholds per cell.
*W* needs a sliding-window max count per (unit, species), which is a single
sorted pass.

### P6. Honesty — built

- **Fitting to the test set.** Picking the best of hundreds of rules on 33
  recordings and then reporting its score is optimistic. The page says so
  plainly, as X1 does. The fix is P13's split: the sweep sees only the
  *tuning* recordings, and the report is scored on the *test* recordings.
- **Small numbers.** A recording-level statistic over 33 recordings carries
  real uncertainty. Show counts beside percentages, and consider bootstrap
  intervals over recordings (open).
- **"Wrong" may be real (V1 F1).** This matters more for lists than for
  windows: a firm call on a species outside the 56 annotated ones cannot be
  judged. Proposed: count those apart as *not in the label set*, in neutral
  grey, and leave them out of firm precision, with a toggle to put them back in.
- **The index floor.** Scores below 0.01 are not stored (0.25 for one Perch
  run), so precision floors whose θ falls below that are not offered.

## What the page shows

Top to bottom:

1. **The rule** (P3): unit, firm condition, check condition. Prefilled with
   *firm* = ≥ 3 windows, *check* = ≥ 1 window, at the sidebar's θ.
2. **A card per model** at that rule, in the navigator's colours: firm right /
   firm wrong / check real / check not there / missed, as C2's average-recording
   bar extended with the check tier. Under it: firm precision, recall after
   review, firm recall, checks per recording.
3. **The sweep** (P5) on the tuning recordings (P13), with the constraint
   inputs.
4. **The rule report** (P14): *Run this rule* over the test recordings, with
   overall performance and the model comparison, or **Full assessment** (P15)
   over every recording in turn.
5. **Recording cards** (as requested): pick a recording to get a species ×
   (annotated, each model) grid. Each cell shows its tier, the number of
   detections behind it, and the best score, with *Open in the Explorer* focused
   on that species. For a reviewer this is the to-check list for that recording.
6. **Species that never go firm**: species that land in *check* or *missed*
   under the chosen rule, which are the candidates for a species-specific rule
   (later, P10).
7. **All the numbers** (collapsed): per-recording and per-species tables with a
   CSV export.

### P13. Tuning and test recordings — built

The page splits the recordings in two, and the split is shown above the sweep:

- **tuning recordings**: the sweep (P5) and the model cards explore on these;
- **test recordings**: these are held back until a rule is chosen, and the
  report (P14) is scored on them.

The default is a seeded random half, which is reproducible and shown as a
list. You can re-draw it or pick recordings by hand. An "explore on all
recordings" switch turns the split off, and the report is then labelled as
scored on the data it was tuned on.

At 33 recordings a half-split is noisy: it reports on about 16, and a
different draw can give a noticeably different answer. That is what the full
assessment (P15) is for.

### P14. The rule report: run the chosen rule over every test recording — built

Exploring ends with a choice: a cell clicked in the sweep, or a rule typed
into P3. **Run this rule** then scores it over every test recording and gives
the final verdict. This is the section that answers "if I process my survey
with this, what do I get?". It is a fixed report, and it does not change as
you keep exploring above, until you run it again.

**What is reported**, per model:

- the headline numbers from P4: firm precision, recall after review, firm
  recall, checks per recording and per hour of audio, and firm errors per
  recording (the mistakes that would ship);
- each next to its **tuning-set value**, so any drop from tuning to test is
  visible (a big drop means the rule was fitted to the tuning recordings);
- **uncertainty**: a bootstrap interval over test recordings for each number,
  with counts shown next to the percentages;
- **against the baseline**: the same numbers for today's C2 behaviour (one
  tier, *k* = 1, at the sidebar's θ), so the gain from the rule is explicit.

**Comparing the models again**, in two ways, because "which model is best"
depends on which of these you mean:

1. **Same rule for every model**: one rule, applied to each model. This is
   simple and directly comparable, but it suits whichever model the rule was
   tuned for.
2. **Each model at its own best rule**: the sweep's best rule, under the same
   constraints, is found separately for each model on the tuning recordings,
   then scored on the test recordings. This is the fair version, because each
   model is read the way that suits it best.

Both come as a side-by-side table and as one chart of the trade-off (recall
after review against checks per hour, one marker per model, with interval
whiskers). The report names the winner under the user's constraints, or says
there is no clear winner when the intervals overlap.

**Below the comparison:**

- **per recording**: one row per test recording, giving each model's firm /
  check / missed / firm-wrong counts against the annotated count. A click opens
  its recording card (page section 5);
- **per species**: how often each species is firm, checked or missed across the
  test recordings, per model;
- **a snapshot**: the rule, the θ source, the split, the models and the date,
  with a download as CSV + JSON. The snapshot is also what P8 saves, so a
  report can be reproduced or quoted in a paper.

### P15. Full assessment — built

A second button next to *Run this rule*: **Full assessment**. It uses every
recording as a test recording once, by **leave-one-recording-out**. The best
rule is tuned on 32 recordings and scored on the 33rd, and this is repeated 33
times. Its numbers are less noisy than a half-split and still honest, because
no recording is scored by a rule that was tuned on it.

**What it assesses.** In each round the rule is re-chosen, so the full
assessment scores *the way of choosing a rule* (your constraints in P5), not
one fixed rule. The page says this in one line. Applied to a hand-typed rule
there is nothing to re-tune, so the full assessment only applies to "best rule
under these constraints" in both model comparisons. A hand-typed rule gets the
ordinary report.

**What it shows**, in the same layout as the P14 report so the two read alike:

- the headline numbers per model, pooled over the 33 held-out recordings, with
  bootstrap intervals;
- both model comparisons (P14), using each round's best rule;
- **how stable the choice is**: how often the 33 rounds picked the same rule as
  tuning on all recordings did, and the spread of the chosen precision floor and
  *k*. A rule that changes from round to round is a sign that the data cannot
  pin it down;
- **the rule to use**: the one chosen on all recordings, with the full
  assessment's numbers as its honest performance estimate.

**Cost.** This is 33 sweeps per model. With P5's precomputation each sweep is
filters and group-bys, so it should take seconds rather than minutes. That
needs measuring. It runs on demand behind a progress bar and is cached by
(rule constraints, θ source, models), so it is never part of a normal page
load.

### P7. Unlabelled data — built (minimal)

Without annotations, page sections 1, 2 (counts only) and 5 still work: the page
produces each recording's firm and check lists, but nothing is scored. This is
how an outside user applies a rule tuned on SNE to their own audio. The
section headings say which parts need labels.

### P8. Saving and exporting a rule — open

A tuned rule is worth carrying around, as threshold sets are. Options:

- (a) add an optional `survey_rule` block to the threshold-set JSON (one file
  holds everything about "how this model's output is read"); or
- (b) keep named survey rules in their own directory, mirroring profiles and
  threshold sets.

Leaning (a): the rule only makes sense with the θs it was tuned with.

Also: a `bex survey` CLI command that writes the firm / check lists for a
dataset as CSV. For most users that CSV *is* the product.

### P9. What happens to Compare's C2 — open

Either keep it as the one-line summary at *k* (and link to the new page), or
move it here entirely. Leaning: keep a smaller C2 on Compare, rebuilt on the
P3 engine, so the two cannot disagree.

## Later (not v1.1)

### P10. Per-species rules

Some species call once an hour and others hundreds of times, so one *k* for
every species is a strong assumption, and page section 6 will show where it
fails. Per-species *k* is fitted exactly like per-species θ and has the same
small-data problems, so it waits until the global rule is understood.

### P11. Abundance and activity

The request also asks how many detections make one bird. A single microphone
cannot count individuals: the same number of detections comes from one bird
singing a lot or from several birds singing a little. What it can measure is
**vocal activity**: detections or bouts per hour. That is a usable index, and
the annotations can test it, because their boxes give the annotated activity.
Proposed for later: an *activity* view that compares each model's bouts per
hour with the annotated bouts per hour, per species, and makes no claim about
individuals. Left out of v1.1 as suggested.

### P12. Rolling and multi-recording units

Rolling windows, and days or sites made of several recordings, for when
datasets have them.

## Build log — 2026-10-05 (branch `v1.1`)

### Where things live

- `bex/survey.py`: the engine. `Condition` / `SurveyRule`; `CurveSource`
  (the aligned frame split by species once, so θ can be refitted on any
  subset of recordings); `fit_bars` (θ per species at each precision floor);
  `evidence`; `tiers`; `outcomes`; `score` and `bootstrap`; `sweep`; `best` /
  `best_shared`; `split`; `full_assessment`. Tested in `tests/test_survey.py`,
  including that a one-tier rule reproduces Compare's species lists exactly.
- `ui/pages/survey.py`: the page, under **Analysis ▾ › Survey rules**.
- `ui/common.py`: cached `get_survey_detections`, `get_curve_source` and
  `get_survey_evidence`.
- `views.SURVEY_COLOURS`: the navigator's colours, with *check* as the pale
  twin of each firm outcome and khaki for "can't judge".

### Decisions made while building (open to change)

- **Open questions answered with a default:** the name is *Survey rules*;
  species outside the label set are *can't judge* and left out of
  precision, with a checkbox to count them as wrong; bouts are not built yet.
- **The default limits** are firm calls ≥ 95% right and ≤ 10 checks per
  recording. Without a checks limit the optimiser drives the firm count to
  the top of the grid (40–50), because checks then cost nothing.
- **The sweep uses one floor for both conditions** and moves the firm count;
  the check count is capped at the firm count. A rule set by hand can still
  give firm and check different floors.
- **Hand overrides are not applied** at the swept floors: they were set while
  looking at every recording, test ones included. The sidebar's own
  thresholds are available as a score bar, with a warning.
- **"Within W seconds"** counts window starts: windows starting at 0, 3 and
  6 s fall within 10 s.
- **The intervals** are 95% percentile bootstraps that resample recordings,
  not (recording, species) pairs.
- **The verdict names any model passed over** because it broke the firm-
  precision limit on the test recordings.

### Seen on SNE (3 models, default limits)

- **Full assessment takes about 40 s** for three models (33 rounds).
- **Held out, each model at its own best rule finds 70–80% of the birds
  after checking**, against 54–56% for today's one-tier list, at a cost of
  8–9 checks per recording (about 8 an hour).
- **BirdNET finds the most (80%)**, but its firm calls fall to 94% right on
  left-out recordings, just under the 95% limit it was tuned to meet. The
  rule is fitted slightly to the tuning recordings, and the report shows it.
- **Stability:** Perch (softmax) picks the same rule in 31 of 33 rounds;
  Perch (sigmoid) in only 19 of 33.

### Revised after the first walkthrough (2026-10-05)

The sweep and the rule looked like two unrelated sections: a sweep click
changed widgets a screen above, out of sight, and the sweep's limits sat
where rule settings would be expected. Now:

- **Choose your rule** is first on the page. **Your goal** comes first: what to
  optimise (most birds after checking, most with no checking, fewest checks,
  or the most trustworthy firm calls) and the limits (firm calls right at least;
  optionally a cap on checks per recording and a minimum share of birds
  found). The goal is what "best" means everywhere: the stars, the report's
  own-best comparison, and the full assessment (`survey.OBJECTIVES`,
  `Constraints.objective`).
- **The rule** is either *optimised automatically* for one model or for all
  models at once, following the goal live, or *set by hand*. Switching to by
  hand starts from the automatic choice. A banner states the rule in force and
  where it came from.
- The bar chart sits directly under the banner, so changing the goal visibly
  changes the lists.
- The sweep became **Explore every rule**, coloured by the goal's objective.
  Clicking a cell makes it your rule, set by hand. The "Use X's best"
  buttons are gone, since the optimiser covers them.
- The recording split moved into a collapsed line under the title.
- The report's verdict ranks models on the goal's objective and checks all of
  its limits.

### Separate check and firm bars (2026-10-05)

An 85% goal for birds found looked unreachable, and the page then quietly
showed an unrelated hand-set rule. Two fixes:

- **When no rule meets every limit**, the page now says which limit is out of
  reach and what is reachable (for example "the most any rule finds within
  your other limits is 83%", or "reaching 85% takes at least N checks per
  recording"), and shows the closest rule, labelled as such.
- **The search chooses the check tier's precision floor separately** from the
  firm tier's. The check bar can now go as low as 0.1, since an expert filters
  it; the firm bar starts at 0.5, and the check bar is never stricter than
  the firm bar. That is 1,215 rules per model instead of 135, still under 0.1
  s each (`survey.FIRM_FLOORS`, `CHECK_FLOORS`, `swept(..., check_floor)`).
  Full assessment now takes about 57 s.
- **Explore every rule** has a check-bar selector, with one grid per setting,
  and says which check bar each model's ★ uses.
- **Seen for BirdNET, within 10 checks:** 83% of birds found (up from 81%),
  with firm after 1 detection at precision ≥ 0.95 and checks at ≥ 0.6. With no
  cap, a check bar of 0.1 finds 98%, at about 29 checks per recording.

### Navigation, About and Tour (2026-10-05)

- **Our own navigation bar** (`app.py`). Streamlit's top bar always puts single
  pages before menus, and cannot colour or right-align an item, so it is
  hidden and BEX draws its own: **Home · 1 · Explorer · 2 · Analysis ▾ ·
  3 · Survey rules** (in the accent colour), with **Set up ▾ · About** to the
  right. Every page keeps its address.
- **About** opens with *Why this exists*: who BEX is for and why. Its "how the
  app follows that flow" list gains a *Decide* step (Survey rules).
- **Home** gains a *Decide* card.
- **The Tour** gains a Survey rules section with three screenshots, and a new
  home screenshot.
- **Renamed *Survey protocol*:** what you leave the page with is a protocol to
  apply to the rest of your data. The address stays `/survey`.

### Each model at its own best (2026-10-05)

"All models at once" optimised one rule shared by every model, which had to
meet the limits for all of them, with "birds found" averaged across models. So
asking for 80% failed whenever one model could not reach it, and the message
quoted the average. It is replaced by **each model at its own best**, now the
default: every model gets the rule that suits it, the banner lists one rule
per model, and the chart, rings, recording card and report each use that
model's rule. Optimising for one model still applies its rule to every model.
When the rules differ, the report shows one view (your rules already are each
model's best). With one shared rule it keeps its two tabs. Full assessment
keeps its "one shared rule" tab for comparing models on equal terms.
