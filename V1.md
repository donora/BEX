# BEX v1 — refinement list

The work between today's app and a first open-source release that people can
install, point at their own audio, and give feedback on. Items are collected by
walking through the app tab by tab; each one says what changes, why, and what is
still undecided. Build order is worked out once the walkthrough is done.

Status key: **built** · **agreed** · **proposed** (not yet discussed) · **open** (needs a decision)

Stage 1 (everything through the Explorer) was built on 2026-09-29 — see the
build log at the end for decisions made during the build and what it turned up.

---

## Name

### N1. BirdUK → BEX (Bioacoustics Explorer) — built

Renamed everywhere: app title and sidebar, docs, the mission diagram, the
Python package (`import bex`), the `bex` command, `bex.toml` /
`bex.example.toml`, the `BEX_CONFIG` environment variable, the threshold-set
format tag (`bex-thresholds/1`), and the folder (`BirdSets/bex`). The app
environment and both runner environments were repointed to the new folder and
have `bex` installed in place of `birduk`. Stored runs and data never
contained the name, so nothing on disk needed migrating.

`bex` is taken on PyPI (an unrelated, dormant PyTorch research package), so
the **distribution name is `bex-bioacoustics`**, which is free as of 2026-09-29.
Once published, people will `pip install bex-bioacoustics` and still
`import bex` and run `bex`, the way scikit-learn installs as `sklearn`.

**Home · Explorer · About · Analysis ▾ · Set up ▾**

- **Home** is the landing page: what BEX is, a primary *Open the Explorer*

## Sidebar — the experiment's global settings

The sidebar should hold exactly the settings that define the experiment being
viewed, set once and read by every tab. Today some of those live inside tabs
(and are duplicated), and one sidebar control no longer means anything.

### S1. Remove the "Model run" dropdown — built

Every comparison tab already uses every complete run, so the dropdown now only
decides:

- which run's manifest the Mission tab shows → manifests move to the Models tab (T2);
- the Explorer's *default* model selection → the Explorer defaults to all models;
- the run the Geofilter forensics tab analyses → forensics gets its own picker,
  limited to runs that have a geofilter (Perch has none), since that tab really
  does look at one run at a time.

### S2. Replace the θ slider with a threshold rule — built

A single θ across models is misleading: each model's scores are on a different
scale, so the same θ is a different operating point for each model. The sidebar
instead sets *how* each model's threshold is chosen, per species. The sidebar
holds only the global rule. What it produces, and any hand overrides, live on the
Thresholds tab (H1).

- **Rule:** max F1 / precision ≥ floor / max F2 / fixed θ. This is the Species
  scorecard's "Operating point" selector moved to the sidebar.
- **Source:** fitted on this dataset, or taken from a saved threshold set (H1)
  fitted elsewhere. That is how unlabelled datasets (anything added with
  `bex scan`) get meaningful thresholds, and that is most of what outside
  users will bring.
- **Fallback** for species with no fitted threshold (too few labelled windows,
  or never annotated). This matters most for the implausible species the
  forensics tab is about, which have no positives by definition. Candidate
  fallback: the model's pooled max-F1 θ (Compare already computes it). The app
  must show which species fell back.

Resolved: the global "fixed θ" rule is one value per model (the scorecard's manual
mode already works this way). A fixed θ for a single species of a single model is
an override on the Thresholds tab (H1), not a sidebar setting.

### S3. Move the rest of the experiment definition into the sidebar — built

Each of these is currently set inside a tab, sometimes twice:

- **Implausibility judge** (geofilter / profile / either) — separate controls in
  Explorer and Forensics today. Sits next to the plausibility profile.
- **Δ (shadowing band)** — two independent sliders (Forensics, Compare). It is a
  definition and should be set once.
- **Threshold rule parameters** — precision floor, minimum predicted windows,
  minimum labelled windows. Compare's sliders become global; the Species
  scorecard currently ignores them and hard-codes `0.95, 10, 1`, so today the two
  tabs can disagree.

The in-tab copies are deleted, not just hidden.

### S4. Global model filter — built

A multiselect of which runs are included everywhere, replacing S1's dropdown.
Useful for dropping a half-scored run, or narrowing to two models.

### S5. Settings summary line — built

A compact line at the foot of the sidebar: dataset · profile · judge · rule · Δ
· models · threshold set (with an unsaved-changes marker). Any screenshot a tester sends back then
records the configuration that produced it.

## Thresholds tab (new)

### H1. See, understand and override every threshold — built

The sidebar rule (S2) gives every species × model pair a θ. This tab shows what
the rule produced and why, and is the only place a θ can be set by hand. This is
what makes the sensible default and full control the same system: a researcher
who never opens the tab gets the rule, and one who wants control has it for
every threshold.

**Resolution order**, shown for every cell: hand override → sidebar rule →
fallback (S2) → no threshold.

**Overview:** a species × model table. Each cell shows θ, which layer set it
(rule / fallback / override), and the precision and recall at that θ. Filterable,
and sortable by "fell back" or "overridden" so the problem cells come first.

**Species view** (search or pick a species):

- one precision–recall curve per model, overlaid, with the candidate operating
  points marked: max F1, precision ≥ floor, max F2, the fallback, and the θ
  currently in force;
- per model, a control to override θ for this species: pick one of the marked
  points, or type / slide a custom value. Clearing the override returns the cell
  to the rule;
- species with no labelled windows have no curve. Show why, and what θ they get
  instead.

**Persistence: named threshold sets.** Overrides are saved as named sets
("custom overrides 1", "Mara — dawn survey", …), one file each in a
`thresholds/` directory. This mirrors how plausibility profiles already work
(named files in `profiles/`, picked in the sidebar). Streamlit session state
alone does not survive a refresh.

- **Choosing:** a "Threshold set" selector in the sidebar, next to the
  plausibility profile, with "none (rule only)" as the default. The Thresholds
  tab edits whichever set is active.
- **Saving:** *Save* updates the active set, and *Save as…* creates a new named
  one. An "unsaved changes" marker shows when the on-screen overrides differ
  from the file. Delete and rename are in the tab, not the sidebar.
- **What a set holds:** the rule and its parameters (S2/S3), the overrides, and
  a snapshot of every resolved θ. The snapshot is what lets a set fitted on a
  labelled dataset be used on an unlabelled one. This replaces S2's separate
  "load from CSV" source. Also stored: name, author (free text), created /
  updated time, and the dataset it was fitted on.
- **Stale overrides:** a θ is only meaningful for the model that produced the
  scores, so each override records the run's model name and version. Loading a
  set whose models have changed flags those overrides as stale and does not
  apply them; nothing is silently reused.
- **Sharing:** the files are plain and human-readable (TOML or CSV + header, to
  be decided), so a set can be emailed, committed alongside a paper, or dropped
  into someone else's `thresholds/` directory. A download / upload button covers
  users who never open the directory.

**Honesty:** overridden cells carry the X1 warning more strongly than rule-set
ones, because a θ hand-picked while looking at the curve it is then scored on is
fitted to that curve.

Existing pieces to fold in: Compare's precision–recall sweep and its
precision-floor / minimum-support sliders (whose parameters move to the sidebar
in S3), and the Species scorecard's "How much of this is the threshold?" chart
and per-species threshold CSV export. What moves and what stays gets decided
when the walkthrough reaches those tabs.

### H2. Precision floor by default, and no θ fitted on too little data — built

**Default rule is now precision floor** (0.95).

**Why max F1 / max F2 looked so bad.** On SNE, max F1 gave window-level
precision of only 0.28 (Perch) and 0.45 (BirdNET) on annotated species. The
cause was a few extremely rare species. With a single labelled window, every
threshold above it scores F1 = 0, so "maximise F1" always reaches down to that
window however deep it ranks. American Goldfinch has one labelled window, and
its max-F1 θ of 0.0005 alone made 49% of BirdNET's wrong detections.
Precision floor never had this problem: those species cannot reach 95%
precision, so they already took the fallback.

**The guard:** *Rule settings → Minimum labelled windows to fit a θ*, default
**10**. Below it a species takes the fallback, and the Thresholds tab says
why. 40 of 56 species (Perch) and 43 of 56 (BirdNET) clear 10, so the rule
still fits the large majority; the rest have 1–9 labelled windows, which is
too few to fit anything. Measured on SNE, the guard removes most wrong
detections at no cost in recall:

| model | rule | wrong windows, before → after | precision | recall |
|---|---|---|---|---|
| BirdNET | max F1 | 33,038 → 6,768 | 0.45 → 0.80 | 0.736 → 0.735 |
| Perch (sigmoid) | max F1 | 49,344 → 15,224 | 0.28 → 0.55 | 0.699 → 0.699 |
| Perch (softmax) | max F1 | 52,393 → 10,853 | 0.26 → 0.63 | 0.692 → 0.692 |
| BirdNET | max F2 | 45,507 → 19,225 | 0.40 → 0.62 | 0.834 → 0.834 |

What remains is what max F1 means: it balances misses against false alarms,
so it will always be less precise than a 95% precision floor. Note that 10
windows is 30 s of song on BirdNET's 3 s grid and 50 s on Perch's 5 s grid.
The old "minimum labelled windows per species" slider only ever affected cmAP,
and is now labelled *Minimum labelled windows to count in cmAP*.

## Compare models

### C1. A dashboard at the sidebar's thresholds — built

The page was six blocks of tables, some at operating points of their own. It
now answers one question: **if you processed your audio with each model, at
the sidebar's settings, what would you get?** Everything is at the thresholds
in force, the same ones the Explorer draws with, so a model looks the same on
every page. Top to bottom:

1. **Precision and recall.** Each model's pooled curve across every threshold,
   with a marker where the sidebar's settings put it. Per-species thresholds can
   put the marker *above* the pooled line; on SNE, Perch (sigmoid) sits well
   above its own.
2. **A card per model**, all visual, in the navigator's colours:
   - *When it reports a bird*: one bar split into correct / filter hid a real
     bird / wrong / filter caught a mistake;
   - *≈ N false detections per hour of audio*: shown detections only, counted
     as events, so one bird wrongly reported across three windows counts once;
   - *When a bird is singing*: found / hidden / missed, per annotated song
     rather than per window, so 3 s and 5 s models compare fairly;
   - *Species by species*: one tick per species with ≥ `min_labelled` labelled
     windows at its share of songs found, with the best and worst named.
3. **Where the models differ, species by species.** Songs found beside "right
   when it says so", one marker per model (colour *and* shape), sorted by how
   much the models disagree. A switch shows average precision instead.
4. **Which species each model finds at all.** All / only one model / some /
   none, each group listing its species.
5. **All the numbers** (collapsed): the summary and per-species tables with a
   CSV export, the cmAP league with its window-grid switch, and the readout
   caveats.

The calculations are in `bex/benchmark.py` (tested in
`tests/test_benchmark.py`). Models have their own palette
(`views.MODEL_COLOURS`: raspberry, teal, gold, violet — charcoal at first,
replaced because the first model read as a grey, "not there" colour). **One
look per model, app-wide**: `views.model_styles` assigns each run a colour and
shape once, oldest run first, so a model is drawn the same way on Compare,
Species scorecard and Thresholds, and a new run joins at the end without
recolouring the others. (The pages had each assigned colours by their own list
order, which drew the same model in two colours.) so a model is never "blue"
where blue means "correct".

**The rule is impossible to miss.** Every number depends on it, so it is not
left to an ⓘ. A highlighted banner under the title reads "Everything on this
page is at one threshold rule: *precision ≥ 0.95*", saying where to change it.
Every section heading carries the rule as a highlighted tag. The chart says in
plain text that its lines are every threshold and its large markers are your
rule, with dashed guides to the axes and a readout of each model's precision
and recall. The rule in words (`RuleSpec.describe()`) sits in the page's ⓘ.

**Moved:** the matched-detection-count league (muddiness, shadowing, filter
errors) now sits on *Geofilter forensics*, where those statistics belong. The
single-species curve and the per-species threshold table are gone from Compare,
because the Thresholds page already covers both.

**Seen on SNE at the default precision floor:** each model is about 95% right
when it reports, finds 48–62% of songs, and makes 15–24 false detections an
hour. **18 of 56 annotated species are found by no model at all**: rare
species whose rule cannot be met fall back to a strict model-wide θ (effectively
1.0 for Perch sigmoid). That is the cost of a 95% precision floor made visible,
and a reason to look at max F1, or at fallback settings, during the stage 2
review.

### C2. What each model would tell you was there — species lists — built (post-v1.0.0)

The answer a biodiversity survey takes from a model: which species were in this
recording? A new Compare section, after the PR chart
(`benchmark.species_lists` / `species_list_summary`, tested).

- A model **lists** a species for a recording when it reports it there at least
  *k* times above that species' θ (*k* is a control on the section, default 1).
  Only presence counts, not timing. Checked against the species annotated in
  the recording, in the navigator's outcomes: correct, wrong, filter hid a real
  bird, filter caught a mistake, missed.
- **Sound-event classes are not species** (`taxonomy.is_species`: a Latin
  binomial). Perch scores ~80 AudioSet classes (*Car*, *Church_bell*), BirdNET
  a few (*Dog*, *Engine*); none belongs on a species list. Mammals and frogs a
  model names count as wrong — they are not in this survey's annotations.
- **One side-by-side chart** (revised after review; it replaced a card per
  model and a listed-vs-annotated scatter, both hard to read): the average
  recording as stacked bars. On the left, green, the species annotated in it.
  Then one bar per model: up to a dashed line at that height, the species that
  are there — named, named only without the filter, missed, so they always add
  up to the green bar — and above it the species it would list that are not
  there, listed or removed by the filter. Under it, one line per model: species
  listed per recording, the share of the species there it names, and the share
  of its list that was there.
- **One recording**: a species × (annotated, each model) grid of outcomes, a
  line per model ("lists 5: 4 right, 1 not there · misses 2 of 6"), and *Open
  in the Explorer*.

At precision ≥ 0.95 on `sne`, BirdNET's lists are the most trustworthy (91% of
listed species were annotated) but name only 56% of the species present — 6.2
listed per recording against 9.9 annotated. Every model under-reports richness,
more so as recordings get busier.

## Species scorecard

### SC1. One bird, as a scorecard — built

The overview (every annotated species, a dot per model) stays as it was, now
titled "… — at `rule`". Everything below the species picker was rebuilt:

- **S1 · The rule up front.** The same banner as Compare ("Everything on this
  page is at one threshold rule: …"), and the rule as a highlighted tag in
  every section heading.
- **S2 · A card per model for this bird**, replacing the grid of numbers and
  the "what each arm did with its chances" bars. It shows the θ and where it
  came from (rule / fallback and why / set by hand), then *when it reports this
  bird* (the navigator's four outcomes), *false detections of it per hour*,
  and *when it is singing* (found / hidden / missed, per song). A button opens
  this species on the Thresholds page. The old section's own red/yellow colours
  are gone: it is the navigator's palette throughout.
- **S3 · Recording by recording**, rebuilt so false detections are as visible
  as finds. For each model, one row per recording:
  - *songs found* is a bar in each cell: blue for the share found, grey (the
    navigator's "missed") for the share missed, labelled found / annotated
    (601/800), so the proportion reads at a glance;
  - *false detections* sit beside it: orange, as events.

  **Colour strength is volume**, on one square-root scale for both columns, so
  2/2 songs is a faint full bar and 601/800 a deep three-quarter one. A model
  that finds 2 of 2 songs but makes 30 false detections shows a faint bar
  beside a deep orange cell. Shading by rate hid that, and shading only by
  count hid the proportion; this shows both. (Grey rather than red for
  "missed" keeps it the same as everywhere else in the app, and away from the
  orange column beside it.) Recordings where the bird is
  not annotated but was reported still get a row, because that is where the
  false detections are.
- **S4 · "How much of this is the threshold?" removed.** The Thresholds page's
  per-species curve covers it and lets you act on it.
- **S5 · "What this bird gets confused with"**, in two panels:
  - *Its crowd* (muddiness): when a model reports the bird, which other species
    clear their own θ within Δ of it, with ⚠ on the implausible ones, plus each
    model's average crowd size (`benchmark.crowd`);
  - *What it is mistaken for* (confusion): the annotated birds reported
    instead in the windows it was missed (`benchmark.mistaken_for`, now at
    each species' own θ).
- **S6 · "Window by window" removed.** "Listen in the Explorer" opens the
  Explorer on the chosen recording, already focused on this bird and scrolled
  to its first song.
- **All the numbers**: window counts (grid-dependent, so not for comparing
  models) and the per-recording table.

Also: Compare's chart line now reads "Lines: one threshold for every species …
Markers: your rule — a threshold per species. A marker above its line means
per-species thresholds beat any single one", which answers the "why is Perch's
marker off its line?" question on sight.

## Geofilter forensics

### G1. What the filter does, as cards and pictures — built

The page used to look at one BirdNET run at a time, at one model-wide θ, as
metrics and tables. It now covers **every included model at its per-species
thresholds** (the sidebar's, as on every other page), over every species the
model can name — most of what a filter removes is birds nobody annotated. The
numbers live in `bex/geofilter.py` (tested in `tests/test_geofilter.py`); the
scalar-θ `stats.py` functions are reused by handing them only reported rows with
θ = −∞. The shared rule banner is now `common.rule_banner` (Compare and
Scorecard use it too); here it also names the judge and Δ.

- **A card per model** (revised after review). Headline: "Hides N% of its
  detections" — of everything reported above its thresholds, the share the
  filter removes — as a bar, the hidden slice at its left. A second bar zooms
  into that slice (dashed guide lines) and splits it: **mistakes removed** (not
  annotated in that window; grey, the navigator's "filter caught a mistake") and
  **correct detections lost** (annotated there; purple, "filter hid a real
  bird"), with counts. Removed is a bold green (#2e8b3e) on this page, not the
  navigator's pale grey, which vanished against the let-through track; the
  track is a darker grey (#dcdad3). CVD ΔE ≥ 45 for every pair. The two add up
  to the hidden total. Then **precision and recall, without → with the filter**,
  each with the change in points (`geofilter.precision_with_and_without`,
  `recall_with_and_without`; recall per song, as on Compare) — precision alone
  can rise while the filter hides nearly everything. A line for windows holding
  an impossible bird. Then **"Always hides N of the M annotated species"** as a
  unit bar, one cell per species, with a *Which species* popover. "Real birds"
  wording is gone: it said neither what was real nor whether hiding it was
  right. Under the geofilter judge a model with no filter says so; the
  circular-profile warning stays, once, above the cards.
- **Birds each model is sure of that should not be here** replaces the score
  histogram and top-15 table: per impossible species, a bar per model for
  detections (or recordings), labelled with how many recordings they spread
  over — one noisy recording vs a persistent soundscape confusion. ⚠ = annotated
  after all (the Explorer's meaning). "Hear it in the Explorer" opens the
  strongest detection.
- **Where the map did the identifying**: shadowed detections per model as a
  stacked bar (same genus dark, different genus light), then the top 12 pairs,
  "bird reported ← rival the filter hid", a bar per model.
- **Revision after review (wording and legibility).** The page names the
  filter every time — "the geofilter", "the plausibility profile" or "the
  filter" (either), from the judge — and says *suppressed* instead of
  "impossible" / "should not be here". The species section is now "The birds
  <filter> suppresses most — detected above threshold, then hidden"; the
  shadow section is "Ties <filter> broke — every bird, every model", with a
  visible one-line caption saying it covers every bird and that the per-bird
  view is next ("How often each model needed the map" read as if tied to the
  listen picker above it, which now sits in its own bordered box). Both bar
  charts are **swim lanes** (`swim_lanes`): one column per model, one striped
  row per bird or pair, shared x. Grouped bars became unreadable once a model
  had no bar in some rows — the colours stopped repeating in step.
- **Second review.** The **ties section is gone** (both charts, and the pairs
  table in *All the numbers*): a location filter suppresses a bird for being
  unexpected at the site, whether or not something else was detected in that
  window, so "the filter broke a tie" misdescribed it. What else is detected
  alongside a suppressed bird belongs in the per-bird section (to be
  redesigned). The swim-lane stripes are a translucent grey with no tooltip
  (they were a light fill: glaring on a dark theme, and they showed their own
  numbers on hover), and the suppressed-birds chart has no end labels — *Order
  by* already says what the bars are. The bird picker lists birds most often
  detected beside a suppressed one first.
- **Third review: muddiness leaves this page.** How confusable a bird is (its
  crowd) is the Species scorecard's question, and it is answered there. The
  "One bird and how close its rivals come" section (the muddiness strip and
  the rivals-up-close charts, with their bird picker) is removed, with
  `geofilter.shadows`/`muddiness` and the matched league's muddiness and
  shadow columns. The page is now only about the filter: the cards, the
  most-suppressed birds (with its listen box) and *All the numbers*. Two
  unrelated bird pickers had sat one above the other, and the lower one's list
  (birds the filter lets through) did not match the dots in the chart under it.
- **Charts follow the viewer's theme** (`common.ink`, from
  `st.context.theme.type`): `style_chart`'s grid, axes, labels and titles, and
  this page's own text marks, have light and dark inks. Hard-coded light-theme
  greys had drawn white gridlines and invisible labels in dark mode, app-wide.
- *(Removed in the third review.)* **One bird and how close its rivals come** absorbed per-species muddiness.
  Pick a bird (ordered by shadowed detections). *How muddy is it*: every species
  reported ≥5 times as a dot on one line per model, x = others within Δ, the
  pick as a named diamond. *Its rivals, up close*: per model, the bird's mean
  **detection strength** (the score lanes' measure — raw scores saturate for
  Perch sigmoid and are not comparable) and each rival's strength in the windows
  they share, as a dumbbell to a tick at the bird's own strength there; orange =
  ruled out by the judge, dot size = how often. "Hear its closest call" opens
  the smallest-gap shadow in the Explorer.
- **All the numbers**: per-model counts, the impossible birds, the pairs, and
  the matched-detection-count league (with its provenance note) in one expander.

Finding, under the **geofilter** judge on `sne`: BirdNET's own filter hides 597
of its 19,171 detections at precision ≥ 0.95 and **542 of those were annotated
birds** (55 mistakes removed, 542 correct detections lost; precision 94.8% →
95.0%, recall 62.2% → 59.8%) — and it always hides three
annotated species (Evening Grosbeak, Hammond's Flycatcher, Williamson's
Sapsucker). Under the profile judge the same card is circular by construction.

## Explorer tab

### E1. Rebuild the "Where the birdsong is" navigator — built

**Today:** one blue bar chart of detection counts for the *primary* model (the
first model in the Explorer's model picker, which defaults to the sidebar
dropdown's model), with a grey ground-truth strip and a purple
"suppressed by geofilter" strip underneath. With a focus species it swaps to one
presence strip per model.

**New:** a stack of small charts sharing one time axis, all clickable to move
the viewport as now:

1. **Ground truth:** annotated species per time bin.
2. **One chart per model**, drawn around a centre line:
   - **Above the line, what the model said:** its detections, stacked by outcome:

     | Segment | Meaning |
     |---|---|
     | correct | detected, annotated at that time, shown to the user |
     | wrong | detected, not annotated at that time, shown to the user |
     | filter caught a mistake | detected, not annotated, suppressed by the geofilter: the filter doing its job |
     | filter hid a real bird | detected, annotated, suppressed by the geofilter: the filter's failure, and the case this project exists to surface |

   - **Below the line, what the model missed:** annotated species with no
     detection from that model in that bin, growing downward.

   Correct + filter hid a real bird + missed = the ground-truth count for that
   bin, so the model charts and the ground-truth chart check each other.

The ground-truth heatmap strip and the separate suppressed-by-geofilter strip are
removed: suppression is now a segment of each model's bars.

**Key:** always visible above the charts, not only in tooltips. It explains the
centre line (up = what it said, down = what it missed) and the four colours.
This chart is the first thing a new user meets, so it has to explain itself
without the caption.

Details to decide while building:

- **What a bar counts.** Window counts are not comparable between models: a 3 s
  grid (BirdNET) produces more windows than a 5 s grid (Perch) for the same
  song, so per-model bars would look like a difference that isn't there. Count
  **distinct species per bin** in every chart, ground truth included. Heights
  are then comparable, and each segment reads as a number of species.
- **What "agrees" means.** Match at the detection-window level, not the bin
  level: a detection is correct if an annotation box of the same species overlaps
  its window (using the `min(0.5 s, box duration)` overlap rule from
  `windows.py`, so the navigator agrees with the scorecard's scoring), then bin.
  A species counts once per bin, in its best outcome.
- **What "suppressed" means.** It follows the sidebar's implausibility judge
  (S3), not only BirdNET's geofilter. Perch has no geofilter, so under the
  profile judge its suppressed segments show what the profile *would* have
  hidden. The key's wording follows the judge.
- **Why misses go below a centre line, not down from the top.** Bars hanging
  from a ceiling are hard to measure (their length depends on where the ceiling
  is) and collide with the upward bars in busy bins. A centre line gives both
  directions one scale.
- **Threshold.** Bars use each model's per-species thresholds from S2 / H1, which
  is what makes the outcomes a fair comparison between models.
- **Unlabelled datasets.** No ground-truth chart and no misses. Model bars split
  only into shown / suppressed.
- **Focus species.** The same layout narrowed to one species: the ground-truth
  chart shows that bird's boxes, and each model's chart shows its outcomes for
  that bird only. This replaces the current three-state presence strips.
- **Colour.** No red/green: it is the most common colour-blindness confusion.
  Four categorical colours checked with a colour-blindness simulator, with
  "filter hid a real bird" the most salient, and always backed by the tooltip.
  Test at the navigator's real size, where segments may be a pixel or two wide.

### E5. Model lanes become score plots — built

**Today:** under the spectrogram, one short lane per model. Each detection above
θ is a window-wide coloured rectangle, up to three per window packed into
sub-rows, hatched if implausible. The height carries no information.

**New:** taller lanes where height means **how strong a detection is**. Each
species detected in a window is a short horizontal line across that window, in
its species colour. Hatched / dashed for implausible, as now. Only detections
that clear their own threshold are drawn. Everything below threshold is for the
window inspector table, which lists every score.

The lane is **pictographic, not a measurement**: it shows which detections are
stronger than which, not their scores. Legibility comes first, and exact numbers
are in the table.

- **Height scale.** Every species' own θ sits on the same baseline, near the
  bottom of the lane (about 15% up), which is shaded to read as "the threshold".
  Above it, height is how far the detection clears *its own* threshold, as a
  percentile among that model's detections: the top of the lane is that
  model's strongest detections. In more detail: the margin is taken in log-odds
  (logit(score) − logit(θ)), then ranked across all of that model's
  above-threshold detections in the dataset.
- **Why this scale.** Raw scores are not comparable between models (a softmax
  readout over 14,795 classes puts nearly everything near zero, while BirdNET
  spreads over 0–1) or between species (each has its own θ). Measuring from each
  species' threshold and ranking within each model gives every lane the same
  shape, so they are all readable.
- **Ranked over the whole dataset, not the current view.** Otherwise a line's
  height would change as you pan along the recording.
- **Axis.** No numeric ticks, just "threshold" at the baseline and
  "strongest" at the top. An ⓘ popover (E4) explains the scale. The lane
  label keeps the model's window length.
- **What the height does not mean.** Heights compare detections *within* a
  lane. A line at the same height in two lanes does not mean the two models
  were equally sure. The popover says so.
- **Height.** Each lane gets real vertical space (roughly a third of the
  spectrogram's height). The figure grows with the number of models, so the
  spectrogram's own height may need to shrink when four or more are shown.
- **Ground-truth lane** stays as boxes (annotations have no score). The inspected
  window stays highlighted in every lane (E3).
- **The per-model strip drawn on top of the spectrogram** (and its "Draw
  detections on the spectrogram" checkbox) probably becomes redundant once the
  lanes carry score. Proposed for removal; decide once the lanes exist.
- **The window inspector table stays** as it is.

## Cross-cutting

### E6. Fewer anonymous grey birds — built

Grey means past the palette's eight colours. On SNE a recording holds about 19
species (detected or annotated), so about 11 were grey, and on average 3–4 of
those were *annotated* birds. That happened because colours went to the
most-*detected* species, and a bird the models miss is rarely detected.

- **Annotated species are coloured first**, by how often they are annotated in
  the recording, and the most-detected fill any colours left over
  (`views.species_palette(..., priority=)`). A recording with eight or fewer
  annotated species has every one in colour.
- **Grey marks are named where they are drawn**: once per unbroken run in each
  score lane, and once per species in the truth lane. In the busiest recording
  (SNE_019, 17 annotated species) the two grey birds are labelled and the
  other fifteen have colours.

Hover-to-identify would remove the need for labels, but it means rebuilding the
figure as an interactive chart. That is a stage 2 option.

### E7. Show right and wrong in the score lanes — built

Under precision floor on SNE_019, 70–100% of each model's wrong detections are
of species annotated *elsewhere in the same recording*. They therefore wore a
truth colour and looked exactly like correct ones: the lanes showed which
species, never whether it was right. Each line now carries a symbol at its top
left:

- a **red ✕**: wrong — the species is not annotated in that window;
- an **amber ⚠**: a real, annotated bird the filter would hide.

No symbol means correct, or a mistake the filter would have caught. Symbols
rather than coloured outlines, because the species palette already uses every
hue an outline could take. A first version with orange and purple outlines
clashed with orange and purple species. The key sits under the figure, always
visible, and `views.lane_lines(..., ann)` returns `correct` using the
navigator's own match (`mark_correct`). The ⚠ never appears under the *profile*
judge on SNE, because that profile was built from the annotations; switch the
judge to *geofilter* to see BirdNET's filter hide real birds (e.g. Fox Sparrow
in SNE_020).

### E9. An audio player in recording time, lined up with the figure — built

Streamlit's player counts from zero for whatever clip it is given, so the 60 s
under a spectrogram labelled 1920–1980 s played as 0:00–1:00, and matching a
sound to what was on screen meant mental arithmetic. `bex/player.py` replaces
it:

- **one timeline in recording time**, with the figure's own ticks, inset by the
  figure's margins so it sits exactly under the time axis;
- **the inspected window as a blue band**, with a **▶ window** button that plays
  just that (the union of each model's window around the inspected instant);
- **click the bar** to play from that point, **▶ span** plays the whole view,
  and a red playhead moves across as it plays, with the time in seconds;
- audio is sent as **MP3**: about 0.5 MB a minute, and every browser plays it.
  OGG would have been smaller still, but Safari's support for it is patchy.

The figure's margins are now fixed in inches, so the player sits directly under
the axis. A playhead drawn *on* the spectrogram itself is not possible while
the figure is a static image in its own frame. The aligned player beneath it
is the practical equivalent, and an interactive figure (stage 2) would allow
it.

### E10. Common names for every model — built

Each model's rows used to take names from that model's own label file.
Perch's is scientific names only, so its rows read "Turdus migratorius" next
to BirdNET's "American Robin". `views.common_name_index` now pools every run's
label file in the store plus the dataset's `species.csv`, and every tab names
species from it. BirdNET's labels alone name 98% of Perch's confident
detections (all 56 SNE species). The rest are mostly not birds (frogs,
insects, "Keys jangling", shown with underscores removed) or birds whose
scientific name differs between the two taxonomies.

A store with no BirdNET run has only the dataset's species list to name from.
A bundled open taxonomy would close that gap: check licences first, since
BirdNET's label file is CC BY-NC-SA and cannot simply be shipped in an
Apache-2.0 repo. Stage 2.

### E11. Remove "Draw detections on the spectrogram" — built

The checkbox and the all-species strip it drew along the top of the
spectrogram are gone; the score lanes carry the same information. A focus
species still shades its detections through the spectrogram. The audio player
also moved from the deprecated `components.html` to `st.iframe`.

### E8. Navigator clicks on model charts — built (bug fix)

Each navigator chart has its own click selection, and a click on one does not
clear another. After any click on the truth chart, its stale selection
shadowed every later click on a model chart, so the view did not move. The app
now acts on whichever selection *changed* (`views.new_click`, tested with
exactly that sequence).

### X2. Explanations behind ⓘ popovers, app-wide — proposed

The same clutter as E4 is on every tab (Forensics, Compare and the Species
scorecard are the heaviest). Apply the same rule everywhere: charts and keys stay
visible, and explanations go behind ⓘ popovers. A consistent pattern makes the
app read as one tool.

### X1. Label thresholds fitted and scored on the same data — built (v1 note only)

A max-F1 threshold chosen on the same recordings it is then scored on flatters
the model, especially for rare species. For v1: a visible note wherever fitted
thresholds are scored on the data they were fitted on, stronger for hand
overrides (H1). Later: fit on one set of recordings and score on another
(`splits.py` already exists).

### Decisions made while building

- **Tab order** is now Mission · Recordings · Models · Thresholds · Explorer ·

- **Threshold sets are JSON** (stdlib, readable, diffable). Model identity is

  detections over the whole recording. They used to come from a fixed score of
  0.25, which left most per-species-threshold detections grey.

### Found during the build — for the stage 2 review

### F1. "Wrong" includes species nobody was asked to annotate — open

The navigator's orange counts every detection of a species not annotated in
that window. But SNE's annotations are exhaustive only for the 56 species they
cover (see `truth.py`). A detection of a species outside that set might be a
real bird nobody labelled, and orange overstates error for it. With Perch's
14,795 classes on their fallback θ, that is most of Perch's orange. Option:
split "wrong" into *wrong* (an annotated species, absent here) and *not in the
label set* (cannot be judged), in a neutral colour.

### F2. Most species live on the fallback θ — open

Only annotated species have curves, so every other class a model can output
(thousands) is thresholded at the model-wide θ. That θ is fitted on the pooled
annotated species, which is a reasonable default but a strong assumption. It
matters most for F1 and for the forensics tab.

### X3. Streamlit deprecations before packaging — built

Every `use_container_width` is now `width="stretch"` / `"content"`, and the app
runs with no deprecation warnings on Streamlit 1.63.
