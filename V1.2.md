# BEX v1.2 — labelling your own data

## Where this sits in BEX

BEX exists so a researcher can find out **which way of analysing their audio
gives a trustworthy answer on their own site**: BirdNET or Perch, raw or
geofiltered, at which thresholds, and under which survey rule. v1.0 and v1.1
built the scoring half of that, but only on SNE, the one dataset that arrived
already labelled. For anyone else's audio, every scored page is empty, because
nothing says what was really there.

**v1.2 adds the first step, labelling, and turns the app into one flow per
dataset, which you can look at two ways — labelled data, scored, or all recordings, unscored:**

```
 Home ──► pick a dataset, or add a new one (and run the models over it)
            │
            ├─ All recordings, unscored ── what the models report, everywhere
            │                    2 · Explorer · 3 · Analysis (unscored) · 4 · Survey protocol (lists only)
            │                                       ▲ switch freely ▼
            └─ Labelled data, scored ───── label a sample, score the models on it, then apply the result to the rest
                                 1 · Label ──► 2 · Explorer ──► 3 · Analysis ──► 4 · Survey protocol
                                                                                  └─► the unlabelled recordings
```

The two views are the same app on the same detections. The labelled view
adds ground truth, and with it every scored number. Most real projects use
both: an expert labels some of the data, and the models, set up on that
sample, run over the rest (F0, F4).

v1.2 has two parts, built in this order:

1. **The dataset flow and labelling (F0–F4, L1–L8)**: the two views, the
   home page and navigation built around datasets, how much to label and
   which minutes, labelling 60 s at a time, labels stored in the same format
   as SNE's, and applying a scored setup to the unlabelled recordings.
2. **Error bars (E1–E4)**: how far each number could be off, and a dataset
   status panel in the sidebar saying what every number rests on.

Status key: **built** · **agreed** · **proposed** (not yet discussed) · **open** (needs a decision)

## What changed from PLAN.md Stage 6.5

The 2026-09-30 labelling plan (PLAN.md Stage 6.5) is the starting point. Two
of its ideas are **dropped** after the 2026-10-08 discussion:

- **No model suggestions while labelling.** Accepting a model's detection as a
  starting box, and a "blind" option beside it, are both gone. Any labelling
  that starts from what a model detected flatters that model when it is later
  scored on those labels. It also steers the labeller to the birds the models
  already find, and away from the ones they miss, which are exactly what the
  benchmark needs to measure. The only model output shown while labelling is a
  coarse activity overview in the navigator (L4).
- **No custom event-log storage.** Labels are stored the way SNE's are (L6),
  so a label set is a file any tool can read, and BEX's truth layer reads
  labels you made exactly as it reads SNE's.

Kept from Stage 6.5: 60 s chunks as the unit of sign-off, only closed chunks
counting as ground truth, named label sets that are never overwritten, the
ground-truth set chosen explicitly, published versions, and box drawing via a
custom `st.components.v2` component, with time-only labels as the fallback.

## The dataset flow

### F0. Two views, not two streams — built (revised 2026-10-08)

*First built as two "streams" chosen per dataset; the first test showed that
read as a commitment that walled one off. Replaced by a view you switch freely.*

Any dataset can be looked at two ways, at any time:

- **Labelled data, scored** — only what has been labelled, every number judged
  against the labels chosen under *Scored against*;
- **All recordings, unscored** — every recording, what the models report, no
  right or wrong.

The switch is at the top of the sidebar, repeated as a chip beside the dataset
name in the top bar (click to switch) and as a line at the top of every page
with a *Switch to …* button. The default is the labelled view when the dataset
has labels, otherwise all recordings; a choice sticks per dataset. Labelling is
never *skipped*, only *not started yet*; steps that need labels say *needs
labels*. Home offers plain actions — *Start labelling*, *Explore all
recordings* — neither of which closes off the other.

In the unscored view, a threshold rule has nothing to fit on, so each model
**borrows the rule fitted for the same model and readout on a labelled dataset**
(SNE, today) and the sidebar says so — otherwise every detection fell below a
NaN threshold and the Explorer was empty.

### F1. Home: pick or add a dataset — built

The home page lists the datasets (SNE, plus any you add) with a **progress
strip** for each, showing how far through the flow it is:

| step | done when |
|---|---|
| Add | audio scanned, recordings table built |
| Run models | BirdNET and Perch have scored every recording, and the spectrogram cache is built |
| 1 · Label | the labelling sample (L2–L3) is closed, or how much of it is; *not started yet* until there are labels |
| 2 · Explore | no completion state; shown as available |
| 3 · Analyse | a threshold set has been fitted on this dataset's labels |
| 4 · Survey protocol | a rule has been saved for this dataset (V1.1 P8) |
| Apply | the saved setup has been run over the unlabelled recordings (F4) |

Clicking a dataset makes it the current one and opens it at the first step
not yet done. **Add a dataset** points BEX at a folder of audio, gathers site
and date metadata, and runs the models (`bex ingest` and the runners, from the
UI). Running the models has to come before labelling, because the Label page's
activity overview (L4) is drawn from their output.

SNE appears as a dataset whose labelling is complete: it was imported, so
step 1 shows as done.

### F2. The navigation bar, renumbered — built

**Home · 1 · Label · 2 · Explorer · 3 · Analysis ▾ · 4 · Survey protocol · About**,
always for the current dataset, whose name is shown in the bar. Each step is
its own page. The pages are numbered in the order you work through them.

### F3. The dataset status panel in the sidebar — built

At the top of the sidebar, on every page, the current dataset's status:

> **my-site** · labels: *my-site v2*
> 4 sites · 31 recordings · 62 h of audio
> **Labelled:** 3.5 h in 210 closed chunks, across 24 recordings and 4 sites
> 412 labelled birds of 38 species
> Labelling sample: 70% closed

This replaces per-page footers. Every scored number on every page rests on
this panel's labelled data, so it is said once, in one place, and it updates
as labelling goes on. Where a page uses a subset (V1.1's test recordings, for
example), the page says so beside the number.

Without labels the panel reads **No ground truth: model output only**, with
the dataset's size, and a link to *Start labelling*.

### F4. Applying the setup to the rest of the dataset — built

Labelling does not stop at scores. Its point is to choose and check a
setup on the labelled sample, then run that setup over everything else:

1. Label a sample (L2–L3).
2. On it, choose the model, threshold set and survey rule, and read how well
   they do, with error bars (Analysis, Survey protocol).
3. **Apply** that saved setup (model + thresholds + rule, V1.1 P8) to every
   recording in the dataset, labelled or not. This is the same machinery as
   the unscored view; it only adds the chosen setup.
4. The output (species lists per recording, detections, activity) goes into a
   results table and a CSV export, with each row marked **labelled** or
   **model output**.
5. The model-output rows carry the setup's measured performance from step 2:
   "BirdNET at *my-site thresholds v2*, rule firm ≥ 3 / check ≥ 1: on the
   labelled sample, firm precision 0.91 (0.85–0.96), recall 0.74
   (0.66–0.81)". That is the honest claim about the unlabelled rows. It holds
   only as far as the unlabelled recordings resemble the labelled sample,
   which the random sample (L3) is there to make likely, and the export says
   so.

On the home page this is the final step of the progress strip (F1). The
Survey protocol page gets an *Apply to the whole dataset* action, and `bex
survey` does the same headlessly.

## Labelling

### L1. The Label page — built

Step 1 of the flow. It holds:

- the labelling plan: how much to label, and the projection as you go (L2);
- the sample: which minutes to label, and *Next chunk* (L3);
- the labelling view: navigator, spectrogram, audio and the box tools (L4–L5);
- progress (L7) and the how-to (L8).

The Explorer stays as it is: a place to look at what the models found, against
the labels once they exist. Labelling no longer happens in it.

### L2. "How much should I label?" — built

You add a dataset and BEX tells you, roughly, how much of it needs labelling
before the answers it gives are worth having.

**What it starts from:** the dataset's inventory (hours, recordings, sites,
dates and times of day) and the question you want answered:

| goal | what needs to be labelled | what limits it |
|---|---|---|
| *Which model is better here?* | enough recordings to separate the two models' scores | the size of the gap between them |
| *How good is a model overall?* (headline precision and recall) | enough recordings for a ±0.05–0.10 interval | variation between recordings |
| *Per-species thresholds* (V1 threshold sets) | enough labelled occurrences of each species | the rarest species you care about |
| *A survey protocol* (V1.1) | some recordings labelled completely, for species-level truth | species per recording, not minutes |

**The answer has to be iterative.** BEX cannot know how much to label before
it knows how many birds are on the recordings, and it only learns that from
labels. So:

1. **Pilot.** A small random sample: say 2 random minutes from each of 10–15
   recordings, spread over sites and times of day. Roughly 20–30 min of
   audio, or an afternoon's labelling.
2. **Estimate.** From the pilot, BEX measures how variable the numbers are
   (bootstrap interval widths, E1), how many species turn up and how often.
3. **Project.** Interval width shrinks roughly as 1/√(recordings labelled), so
   BEX projects how much more is needed to reach the width you asked for, as
   a range ("about 25–40 more minutes, spread over at least 20 recordings"),
   never as one exact figure.
4. **Repeat.** The projection updates as labels arrive (L7).

Before the pilot there is a rule-of-thumb starting table, labelled as such.
For example, a proportion near 0.8 needs about 60 independent units for ±0.10
and about 250 for ±0.05. Minutes from the same recording are not independent,
which is why the guide counts **recordings** and **sites**, not just minutes.

**Rare species set the cost.** For per-species goals, the guide lists the
species seen so far with their rates, and says plainly which could reach a
usable threshold with a sensible amount of labelling and which could not ("*X*
turned up twice in 30 min; a threshold for it needs ~50 occurrences, roughly
12 h of labelling at this rate").

### L3. Which minutes to label: a random sample — built

If you label the minutes where the models fired, the birds the models missed
are under-sampled, and recall comes out too high. So BEX draws the chunks to
label as a **stratified random sample** of 60 s chunks (spread across sites,
recordings and times of day) and serves them in order. *Next chunk* goes to the
next one in the sample.

- You can still label any chunk you like. Those chunks are marked **chosen by
  hand**. They count as truth, but the headline numbers come from the random
  sample by default, and the status panel (F3) shows both counts.
- The sample is stored with the label set, so it is reproducible and can be
  extended (draw more, keeping the strata balanced) without disturbing it.
- The sample is a mix of **minutes from many recordings** (the default unit)
  and **a few recordings labelled completely**, because V1.1's survey-protocol
  scoring needs whole recordings: a species list for a recording can only be
  judged if every minute of it was labelled. How many whole recordings is set
  by the goal (L2). It is zero unless you want a survey protocol.

### L4. The activity overview in the navigator — the only model guide — built

The labelling view keeps the Explorer's whole-recording **navigator** at the
top. On it, and only there, BEX shows where the models think there is bird
activity:

- one grey *activity* band along the recording, wherever BirdNET or Perch has
  any bird class above a **permissive** θ (non-bird classes such as Perch's
  engines and music are excluded);
- **no species names**, no colours by species, no per-model lanes;
- coarse on purpose: at the navigator's scale it shows that the dawn chorus is
  busy and 03:00 is quiet, not where individual calls are.

**Nothing from the models appears on the spectrogram or under it.** You go
through the chunk 60 s at a time, listening and reading the spectrogram, and
label every bird you hear, whether or not the overview marked activity there.

The overview's purpose is orientation: knowing a recording is mostly silent,
or that one stretch is very busy, before you start. It does not decide which
chunks you label (the random sample does, L3), so it cannot bias the sample
towards what the models detect. A note beside it says it is a permissive
model guess, that it misses things, and that closing a chunk means listening to
all of it.

### L5. Labelling a chunk — built

- The view shows one 60 s chunk: the spectrogram, the audio player on the same
  time axis, and the boxes drawn so far.
- Draw a box (time × frequency) and give it a species from a searchable list
  (common names and the taxonomy's keys). Edit, move and delete boxes.
- **Unknown bird** is a label for a bird heard but not identified. It counts
  as "a bird is here" and as no species for species-level scoring, and the
  status panel counts them.
- **Close the chunk** when every bird heard in it is labelled. Only closed
  chunks count as ground truth, so a chunk nobody finished never reads as "no
  bird here". A closed chunk with no boxes means *listened, no birds*.
- Editing a closed chunk takes an explicit *Reopen*.

### L6. Storage: the same format as SNE — built

SNE's labels are a table with one row per box (`annotations.csv`: Filename,
Start Time (s), End Time (s), Low Freq (Hz), High Freq (Hz), Species eBird
Code). BEX already stores them as `store/datasets/<name>/annotations.parquet`
in `ANNOTATIONS_SCHEMA` (recording_id, start_s, end_s, low_hz, high_hz,
species_key). **Labels made in BEX are stored the same way.** A label set is a
folder:

```
store/datasets/<name>/labels/<set>/
    annotations.parquet   one row per box, ANNOTATIONS_SCHEMA, plus
                          labeller and labelled_at columns (ignored by
                          anything that reads only the standard columns)
    chunks.parquet        one row per 60 s chunk: recording_id, start_s,
                          state (open/closed), closed_by, closed_at,
                          in_sample (random / by hand)
    meta.json             derived_from, sample settings, created
    v1/, v2/ …            published versions: frozen copies of the two files
```

- `chunks.parquet` is the one thing SNE's format has no place for. It records
  which stretches were listened to, which is what turns "no box here" into "no
  bird here". An imported exhaustive set such as SNE gets one generated, with
  every chunk closed.
- **Export** writes `annotations.csv` with SNE's column names (species as the
  canonical key, plus the eBird code where the taxonomy has one). Re-importing
  that file through the same path as SNE gives the same set back.
- The truth layer (`truth.py`) reads a label set's `annotations.parquet`
  through the same function it uses for SNE's, restricted to closed chunks.
- **Edits and concurrency:** a save rewrites the set's files atomically and is
  refused if they changed since the page loaded them. History comes from
  published versions, not an edit log. Whether also to keep a timestamped
  backup on each save, which is cheap at this size, is open.
- The ground-truth set and version are chosen in the sidebar, and truth caches
  are keyed on (set, version).

### L7. Progress — built

On the Label page:

- **Coverage:** chunks closed against the sample, and a small grid of sites ×
  times of day showing gaps.
- **What has been found:** species count, per-species occurrences, the number
  of unknown-bird labels.
- **Species accumulation curve:** species found against minutes labelled. When
  it flattens, labelling has stopped turning up new species, which is a better
  stopping signal than a fixed number of hours.
- **The plan's projection (L2)**, refreshed: "headline recall interval is
  currently ±0.14; about 20 more minutes across 8 new recordings should bring
  it under ±0.10."
- **Labelling rate** (minutes of audio per hour of work), so the projection can
  be given in hours of your time.

The headline figures from here also feed the sidebar status panel (F3) and the
home page's progress strip (F1).

### L8. How-to and importing — built

A short guide on the Label page (and a section in TOUR.md) for someone new to
annotating: what closing a chunk promises; why the sample is random; how much
to label; reading a spectrogram (wind, rain and insects against birdsong); when
to use *unknown bird*; and a worked pilot on the demo set.

**Importing existing annotations** (the README roadmap item) uses the same
path as SNE: a CSV in SNE's columns, or Raven selection tables and Audacity
label tracks converted to it. The import asks *were these recordings labelled
exhaustively?* If yes, every chunk is closed. If no, the boxes count only as
presence (usable for precision, not recall).

## Error bars

### E1. One method everywhere: resample the independent unit — built (Compare, Survey protocol, Label)

V1.1's `survey.bootstrap` resamples **recordings**, because a busy recording's
windows rise and fall together. v1.2 makes that the rule for every number BEX
reports: cmAP and per-species AP (Analysis), precision and recall at θ, and the
survey numbers.

- With labels from a sample of chunks, the unit is still the recording: each
  resample draws recordings, with their closed chunks.
- Percentile intervals at 95% from 1,000 seeded resamples, as in V1.1.
- Where a number rests on fewer than ~5 recordings, BEX shows no interval and
  says *too little labelled data to say how far this could be off*.

### E2. Model comparisons use paired differences — built

Two models scored on the same recordings are correlated, so the difference
between them is much more precise than either number alone. BEX resamples once,
computes both models on each resample, and gives an interval for the
difference: *BirdNET's recall is higher by 0.08 (0.03 to 0.13)*, or *no clear
difference: −0.02 to +0.06*. This replaces V1.1 P14's "intervals overlap"
wording, and it is what L2's "which model is better here?" goal sizes against.

### E3. What each number rests on — built: in the status panel

The sidebar status panel (F3) states the labelled data once for the whole
dataset. Per-species rows still show their own count of labelled occurrences,
because that differs species by species, and species below the V1 *minimum
labelled windows* setting are greyed out with the reason given.

### E4. Open questions

- Recording-level or site-level resampling when there are few sites. Proposed:
  recordings, stratified by site, with a warning below ~5 sites.
- Fitted thresholds are scored on the data they were fitted on (V1 X1). Error
  bars do not fix that bias; it needs V1.1 P13's tuning/test split on the
  Analysis page too. In or out of v1.2?

## Build order (as planned)

1. **Label sets on disk (L6):** the folder layout, chunks table, versions, CSV
   export and import. SNE becomes the first set, and `truth.py` reads from it.
   Library only, with tests.
2. **The dataset flow (F0–F3):** home page with progress strips, current
   dataset, renumbered navigation, sidebar status panel, the ground-truth set
   choice, and the *needs labels* / *unscored* marking on every page.
3. **Add a dataset from the UI:** scan, metadata, run the models. At this
   point the unscored view is complete.
4. **The Label page, time-only labels first:** sample (L3), chunk view, species
   picker, close and reopen. Works end to end before box drawing.
5. **Box drawing component** (`st.components.v2`).
6. **The navigator's activity overview (L4).**
7. **Plan and progress (L2, L7), how-to and importers (L8).**
8. **Error bars E1–E3** across Analysis and Survey protocol.
9. **Apply to the rest (F4):** the results table and export, carrying the
   measured performance and its intervals. This comes after E1–E3 because the
   claim it attaches needs them.
10. TOUR, README and About updates.

## Decisions still open

1. How many whole recordings go in the default sample next to the random
   minutes (L3), or none until a survey protocol is the goal?
2. The activity overview: the union of BirdNET and Perch, and at which
   permissive θ (L4)?
3. A backup copy on every save, or published versions only (L6)?
4. Whether the error bars ship in v1.2 or become v1.3 if labelling runs long.

Everything above marked *built*, with 308 tests passing (32 new, 1 skipped), the app tests
rendering every page against the real SNE store, and headless walks through the
whole flow: a new dataset added from Home, spectrograms built, BirdNET launched
from the app, a label set created, chunks labelled and closed, every page scored
against the partial set, a setup saved and applied, and `bex survey` on the CLI.

### Where things live

- `bex/labels.py` — label sets: chunks, boxes, sign-off, versions, the sample,
  progress, truth (`Truth`, `load_truth`, `within`), CSV / Raven / Audacity in
  and out. `tests/test_labels.py`.
- `bex/uncertainty.py` — recording-level bootstrap and paired differences for
  Compare's headline numbers; `survey.paired` does the same for the survey
  page's. `tests/test_uncertainty.py`.
- `bex/setups.py` — saved survey setups and `apply` (F4). `tests/test_setups.py`.
- `bex/flow.py` — each dataset's step states for Home. `tests/test_flow.py`.
- `bex/runners.py` — starting a model runner from the app.
- `bex/views.py` — `activity_windows`, `activity_bins` (L4), `mel_row_to_hz`.
- `bex/truth.py` — `align_run(truth_ref=…)` scores only closed time; caches
  keyed on the ref (`truth/<dataset>/sets/<ref>/`), the imported layout unchanged.
- `ui/pages/label.py` (new), `ui/pages/home.py` (rewritten), `ui/sidebar.py`
  (ground truth, status panel), `ui/common.py` (every truth-dependent cache takes
  the ref), `app.py` (navigation), Survey protocol (save and apply sections).
- CLI: `bex labels DATASET`, `bex survey DATASET --setup NAME [--truth REF]`.

### Decisions made while building (open to change)

- **The sample is its own file** (`sample.parquet`), not a column of
  `chunks.parquet`: it exists before any chunk is touched. Boxes carry a
  `box_id` beside `labeller` and `labelled_at`, so one box can be edited.
- **A working copy's ref carries a hash of its files** (`name@w<hash>`), so
  every cache built on it expires the moment it is edited; old working caches
  are pruned when a new one is built.
- **Partial truth, two rules.** Window-level numbers (AP, precision, recall,
  thresholds, the geofilter page) use only windows wholly inside closed chunks;
  a window straddling a closed and an open chunk is dropped. Whole-recording
  numbers (Survey protocol, Compare's species lists) use only recordings closed
  end to end. The Explorer shows a partly labelled recording **unscored**. For
  an exhaustive set (SNE) both rules keep everything, so v1.1's numbers are
  unchanged.
- **Unknown bird** is kept in the set and counted, and left out of scoring.
  The two-candidate label ("X or Y") was dropped: SNE's format has one species
  per box.
- **The activity guide's bar** is per model: the score its top 30% of windows
  clear across the dataset (adjustable), over species classes only. That is
  permissive by construction and needs no per-model θ.
- **Box drawing uses `streamlit-image-coordinates`' click-and-drag**, already a
  dependency, instead of a custom component: drag corner to corner, the box
  appears dashed, name it, add it. No rubber band shows during the drag.
  Editing a box is select-a-row then change species or delete; moving a box by
  dragging is not built.
- **History is published versions**, not an edit log; there is no per-save
  backup (decision 3 below).
- **Ground truth follows the data until someone chooses.** The sidebar's
  default is the imported annotations, else the newest set's working copy;
  once picked by hand it stays. Choosing *explore without labels* on Home sets
  it to none.
- **A setup is self-contained**: rule, the θ table at the two score bars it
  uses, judge, profile, and the performance on the test recordings with
  intervals. It applies to any complete run of the same model identity, on any
  dataset. Applied to a dataset, recordings labelled end to end take their
  labels as the list (model verdict alongside); the rest get the model's list.
- **Home's Add a dataset** scans a path typed in (Streamlit cannot browse
  folders); model runs start as background processes with logs under
  `store/datasets/<d>/jobs/`. Editing BEX's code while one runs breaks it.

### After the first test (2026-10-08)

- **Setting up happens inside the dataset's card on Home**: a spectrogram bar
  and build button, then a bar per model with its Run button, refreshing every
  few seconds while a run goes. "Continue: Run models" used to send you to the
  Models page, which only said nothing had run.
- **Unreadable files are repaired at the spectrogram step** (`repair.build_mel`):
  the SNE stick's 17:00 recordings make libsndfile lose sync, which stopped the
  first build halfway. The step reads every file end to end anyway, so a file
  that fails is re-encoded into `store/repairs/<dataset>/` and the build goes on;
  model runs read the repaired copy. Run buttons wait until the spectrograms are
  done for that reason. `bex melcache` does the same.

- **A finished run no longer reads as running.** The app starts runners as
  its children, and a finished child stays a zombie until reaped, which the old
  `kill(pid, 0)` check counted as alive. `runners.job` now reaps it and keeps
  the exit code; a run that fails says so on the card.
- **"Models run" is not ticked while any model is still running**, so the
  card's setup section stays until every run has finished (then folds into a
  *Spectrograms and models* expander, with *Add a model*). **"Explored" is
  ticked once the Explorer has been opened** on the dataset, not merely when it
  could be.

- **Each dataset has its own plausibility profile**, chosen when it is added
  (*Suggest from the location* picks the profile whose `bbox` in profile.toml
  contains the coordinates, the tightest if several do; none covering it means
  you choose). It is stored in the dataset's meta.json, is the sidebar's default
  for that dataset (the sidebar keeps a choice per dataset), is passed to model
  runs started from Home as `--profile`, and can be changed on the card. The
  config's `[defaults] profile` is now only a last resort for datasets added
  before this.

- **Upload a plausibility profile** (Home, beside *Add a dataset*): a CSV with
  one row per plausible species — `species_key` (scientific name; a
  `common_name` or `scientific_name` column works instead, matched to the
  models' species), optional `tier` (0 national list, 1 regular, 2 vagrant,
  3 implausible; 1 if missing), any other columns kept — plus a display name,
  region and an optional bounding box for location suggestions. Names that
  match no species are listed and the upload refused. The UK starter list
  downloads as a template. `profiles.profile_from_csv`, `save_profile(bbox=…)`.

- **Boxes are made with two clicks, not a drag**: the first drops a large
  corner marker with guides across the spectrogram (time and frequency shown,
  with *Cancel*); the second, the opposite corner. In between you can listen,
  or step to the neighbouring minute.
- **Boxes may cross a minute boundary.** The labelling view shows 5 s of each
  neighbouring minute, shaded, and a box can run into it; ◀ ▶ step to the
  previous / next minute of the same recording, keeping a first corner, so a
  long bout is finished with its second click there. In the store a box counts
  as truth in **every** closed minute it touches (`labels.chunks_touched`), and
  can only be changed while every one of those minutes is open, so editing it
  never alters a signed-off minute. The box list marks crossing boxes ↔.

- **Plan and sample, simplified.** The goal picker, its explanations, the
  rules-of-thumb table and the chunks / whole recordings / seed form are gone.
  One question remains — *how many minutes to label?* (5 suggested to start,
  5 more after) — and BEX picks them at random, balanced across sites, times of
  day and recordings; the seed is the sample's size, recorded, so every draw is
  still reproducible. *How much more?* stays below it. Whole recordings, which
  only the Survey protocol needs, are added from there: when it has too few,
  it offers a button to add them to the labelling sample.

- **Suggestions, on request, after the box** (revises "What changed from
  Stage 6.5"). Labelling without help is hard for non-experts, so once a box is
  drawn — never before — *💡 Suggest birds* lists what the models heard inside
  it: each model's best score over the windows the box overlaps, ranked within
  the model, combined across models by summed 1/rank (scores are not comparable
  between models; agreement counts), sound-event classes left out, species not
  in the plausibility profile marked ⚠. Each row links to Xeno-Canto and has
  *Use*. The protection kept: the models never say *where* to look, nothing is
  shown unasked, and every box records whether suggestions were viewed
  (`assisted`; *Suggestions Viewed* in the CSV), with the share shown on
  *Progress*. Tested on an expert-labelled American Robin call in SNE: ranked
  first. `views.box_suggestions`.

- **Hear a box on its own.** The player under the labelling spectrogram marks
  a box on its timeline and adds *▶ box* beside *▶ span*: the box just drawn
  (before it is named), or the one selected in the chunk's box table. Its times
  read m:ss to match the spectrogram (`player_html(window_label=, clock=)`; the
  Explorer's player is unchanged).

- **Fixed: a phantom first corner after *Discard*.** The click component
  returns its last click on every rerun; a click made while a box waited for
  its species (a stray or double click) was skipped without being marked seen,
  so after *Discard* it came back as a new corner. Every click is now marked
  seen whether used or not, in a set rather than "the last one". Reproduced and
  checked in the browser: draw + discard, stray click + discard, double click +
  discard, and leaving and returning to a minute.

- **A red ✕ on the box being drawn** (top-right corner) discards it, as
  *Discard* does; other clicks while it waits are still ignored.
